# Plan: Finish the StartSpace MVP

Status: done  
Date: 2026-09-02

## Goal

Complete the remaining non-optional work in `.plan/000-backlog.md`.

## Scope

Add portable backup/restore to Settings, document its storage format, and make
the clone-to-load-unpacked developer path reproducible. Store publication is
optional release work and remains outside MVP completion.

## Assumptions

- Chromium remains the supported MVP browser because workspace access depends
  on the File System Access API.
- Restore is non-destructive toward files not represented in a backup.

## Open questions

None. Future compressed archives and cross-profile bookmark-ID reconciliation
can be evaluated after MVP feedback.

## Steps

1. Define and validate a versioned backup schema.
2. Export workspace files and extension-owned state from Settings.
3. Restore validated data into a user-selected workspace.
4. Verify generated extension artifacts and document load-unpacked steps.
5. Run unit tests and the production build, then update the backlog.

## Validation

- Vitest covers valid, malformed, unsafe-path, and unsupported-version backups.
- `bun run build` type-checks, builds, and verifies the MV3 output in `dist/`.

## Risks

- Base64 increases backup size; accepted for a dependency-free MVP format.
- A failed filesystem write may leave earlier restored files updated. The UI
  explains that unrelated files are never deleted; future work may add staging.

## Rollout

Ship with the Chromium unpacked build after manual Settings smoke testing.

## Rollback

Remove the Settings backup controls and backup modules. Restore never changes
the schema of the underlying workspace files, so no data rollback is required.
